# Lane `lane/force-1` -- CDX colouring-lever pass

Four colouring residuals were read with the instrumented uopt CDX profile
(`~/Desktop/dev/ido-instrumented/cc`, `CDX_LOG=1`). ~18 builds. No match was
reached and no source file in this lane is changed from as-found. Two of the
four are proved *not* colouring residuals at all; one is proved almost fully
colour-reachable with the residual isolated to a single cfe-canonical operand
order; one had its owning-pass claim corrected and a real source lever found.

## Reopen gate

`overlay40FadeRecords` and `func_800498FC` were `already-integrated/exhausted`;
pins were committed first and both re-confirmed `base-only` with `--base HEAD`.
`frontSetScreenMode` and `func_800056A4` were already base-only.

---

## 1. `overlay40FadeRecords` -- NOT colour-reachable

**Webs.** 21 allocator decisions, *all p2*, every one `bestcost=0.000000`, taken
in strictly ascending web number. Save cost is inert; assignment is a pure
function of web numbering. Coloured webs: 0=v0, 4=v1, 7=a3, 13=a2, 29=v1,
31=a1, 35=a0, 39=a2, 46=s0, 51=a1, 57=a3, 61=t0, 63=t1, 75=a3, 79=t0, 82=t2,
117=t0.

**The residual.** 3 words, `aligned_register=3`, pool lanes equal at 27 slots,
temp lanes identical 34/34. Rows 3, 4 and 9 only: the target loads `gOverlay40BlendCurrent` into v1 and copies it to v0; we load
into v0 and copy to v1. Both sides end with `current` in v1 and `output` in v0 --
the difference is *which web owns the load's definition*.

**Force results.**

| Force (`CDX_PROC=0`) | Result |
|---|---|
| `p2:w0=c2` | 3 -> **13** words, 0 declined; cascade w4 v1->v0 and w29 v1->v0 |
| `p2:w0=c2,p2:w4=c1` | identical object (`sha1=4c4fa84b3c39`) -- the cascade already did it |
| `p2:w0=c2,p2:w4=c1,p2:w29=c2` | 2 declined, same object |
| `p2:w0=c2,p2:w29=c1,p2:w4=c2` | 2 declined, same object |

**Verdict: unreachable by colour.** `CDX_DETAIL_WEB=0` shows web 0 at `bb=0`
with `numintf=20` and `save=50.83` -- it is the long-lived `output` web, live
from the entry block to the `gOverlay40BlendOutput` store. It is the only web
at rows 3/4, and the target has v1 at rows 3/4 but v0 at the store. So the
target's load definition is *not* in web 0: reaching it needs a different web
*partition* (the copy coalesced the other way), which no colouring can produce.
Forcing w0 to v1 costs 10 words elsewhere, and w29 cannot then take v1 because
it interferes with w0.

**Source lever tried.** The natural current-origin spelling
(`current = gOverlay40BlendCurrent; output = current;`): rows 3, 4 and 9 come
out **byte-identical to before** and the object regresses to 16 words
(`sha1=d31ba4f43c9b`, web 29 v1->v0). cfe canonicalises the copy chain, so
assignment order is inert here exactly as it is at relational operands. This
independently confirms the shard's "exhausted current-origin form".

## 2. `frontSetScreenMode` -- 7 of 8 words colour-reachable, 1 word is not

Proc ordinal **23** (6 webs, all p2, all `bestcost=0`, all `save` between 0.5
and 3.0 -- numbering-only).

**Numbering, before and after.**

| Form | web -> colour | pool lane |
|---|---|---|
| as-found | w5=a0 w7=v0 w8=v1 w13=a1 w33=a2 w34=v1 | `a2 a2 v0 a1 v1 v1 v1 v1` |
| `modeBits & 2` | w5=a0 w8=v0 w13=v1 w34=a1 w35=v0 | `a1 a1 v0 v1 v0 v0 v0 v0` |
| target | -- | `a1 a1 v1 v0 v1 v1 v1 v1` |

**The source lever that moved it.** Writing the second bit test as
`modeBits & 2` instead of re-spelling `(screenMode & 3) & 2` shortens the raw
`screenMode & 3` web so it dies at the `D_8007C090` store instead of living
past it. That alone puts the `&D_8007C090` pointer web on the target's **a1**
(slots 0 and 1, previously a2) and reduces the rest to one clean v0/v1
bijection. Confirmed with a second CDX capture, not from the source diff.

**Force result -- reachability proof.** On that form,
`CDX_PROC=23 CDX_FORCE=p2:w8=c2,p2:w13=c1,p2:w35=c2` gives **`words=1`**, 0
declined, `insns=32`, and **pool lanes identical 8/8**. Seven of the eight
words are legal in our web graph and one numbering lever away.

The same force on the as-found form declines twice (`w13=c1` forbidden
`0x70000000`, `w33=c4` forbidden `0x78000000`) and lands at 21 words: the
as-found web graph cannot host the target assignment, the `modeBits & 2` one
can. That is the measurable difference between the two forms.

**The one word that is not reachable.** Row 5: the target's equality branch
takes the memory load as its first operand and a pool register as its second;
ours takes them the other way round and on a different web. Both the register *and* the operand order differ. The
target compares the memory load against the **untruncated** `screenMode & 3`;
every form we can spell compares the u8-truncated `modeBits` web.

| Spelling | Result |
|---|---|
| `mode = screenMode & 3; modeBits = mode;` | 31 insns -- the u8 truncation is copy-propagated away |
| `modeBits = screenMode & 3; mode = screenMode & 3;` | byte-identical to the above (`sha1=8f4f8ab0235f`); CSE merges them |
| both bit tests via `modeBits`, store via `mode` | 32 insns but 22 words, 5 opcode diffs |
| `modeBits = screenMode & 3; if (*modeState != (screenMode & 3))` | 32 insns, 19 words; `modeBits` coalesces onto **a0** |
| `if (mode != *modeState)` (operands reversed) | branch operand order **unchanged** -- cfe canonicalises `!=` as well as the relationals |

The truncation only survives when its result has a widening consumer, and that
consumer is the compare -- which is precisely the site that must read the
untruncated value. The two requirements are mutually exclusive in every
spelling tried. `finalize_plateau.py` was not run: the `modeBits & 2` form is
19 words unforced against the as-found 8, so it is not strictly better, and the
tree is left as found.

## 3. `func_800498FC` -- not a colouring residual; owning-pass claim corrected

**The lane-length gate fires.** Target pool lane **15** slots, candidate **16**;
target temp lane **26**, candidate **25**. This is a *population* difference,
not a rotation, and no colour lever can close it -- the same shape
`overlay43FilterImage` had. The plateau's "one four-web integer allocation
bijection" is falsified: the extra pool web is the `flags & 0x80` value, which
the target keeps in the ugen ring and we colour into a pool web.

**Source lever found.** Testing `record->value1E` instead of re-spelling
`(u8)(flags & 0x80)` removes the pool web entirely: **pool lanes become
identical 15/15** and the temp lane matches through slot 15. Adding the
schedule half -- moving `record->status = 0xFF;` above the `state` if/else, so
its constant carries the lower source line as1 needs to hoist it -- takes it to
temp-lane agreement through slot 19, `opcodes` 16 -> 6, words 23 -> 13.

Still 13 words against the as-found 9, so not strictly better and the tree is
left as found. What remains is a pure as1 line-order question, not a colouring
one: the target materialises the 0xFF constant sixteen rows
before it stores `status`, and stores `status` after `state`, and neither source order reproduces both.

**Next lever for this function is ugen/as1, not uopt.** Once the population is
closed by the `value1E` read-back, the residual belongs to the ring and the
list scheduler.

## 4. `func_800056A4` -- no colouring residual exists

**Pool lanes are identical, 3/3.** The whole 8-word residual is a ugen temp
ring **rotation of +1** first visible at ring slot 3 -- the target
reuses the temp its base address already occupies where we pop a fresh one -- across six one-step web substitutions
that form a single ring shift. `owning_pass=ugen-temp-ring`.

uopt's colouring is already exact, so `CDX_FORCE` has nothing to act on and no
build was spent on one. The lever is a pop count, which the CDX profile cannot
see; it needs `DKWB_UGEN_TRACE=1` and the free-list trace. Recorded as out of
scope for the colouring lever rather than as unreachable.

## Reusable results

1. **Save cost is inert in p2 -- reconfirmed twice.** Both
   `overlay40FadeRecords` (21 decisions) and `frontSetScreenMode` proc 23 (6
   decisions) are entirely p2 with `bestcost=0.000000` throughout and visit in
   strictly ascending web number.
2. **cfe canonicalises `!=` operand order, not only the relationals.** Writing
   `mode != *modeState` for `*modeState != mode` produced the identical
branch operand order. Extends the pool-spike finding from `>=`/`<` to equality.
3. **Shortening a web's live range is a numbering lever.** Re-spelling one use
   of a CSE'd expression as a use of the narrower local (`modeBits & 2`)
   removed an interference and moved a *different* web (the pointer) onto its
   target colour. Cheaper than adding or reordering a local, and it does not
   shift downstream numbers uniformly the way an added local does.
4. **Read the lane lengths first.** `func_800498FC` was recorded as a four-web
   bijection and is a population difference of one; the check costs nothing and
   would have saved the whole colouring approach on that function.
5. **A pool lane that already matches means uopt is not the owner.**
   `func_800056A4` needs no force experiment at all.
