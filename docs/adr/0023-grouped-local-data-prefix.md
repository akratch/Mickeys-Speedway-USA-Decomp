# 0023. Complete mixed data prefixes with ordered LOCAL providers

Status: Accepted
Date: 2026-10-24

## Context

Overlay 101's genuine initialized prefix contains a byte-pointer array and
three active signed counters in one compiler-owned aggregate. Its pointers
name mutable character arrays in two already-owned complete C inputs. IDO
emits actual global object bases with zero symbol sizes. The first provider
starts the runtime RO partition; the second follows its complete allocation.
ADR 0022's one-provider all-pointer guard deliberately excludes this case.

## Decision

Add one explicit grouped-provider acceptance case to the existing data-only
module path. Preserve ADR 0021 and ADR 0022 guards and default refusals.

- The source is one genuine complete sized global C aggregate in writable
  initialized DATA, with no text, RO, BSS, COMMON or assembly fallback. Scalar
  fields are real source fields; no synthetic shape witness encodes a site list.
- An explicit ordered group declares complete ordinary C provider inputs and
  the first input's start as runtime RO origin. Ordinary GNU ld derives every
  group-relative symbol value from actual definitions, allocations and order.
  No numeric binding, name-coordinate decoder, retained-site identity lookup,
  guessed symbol extent or fake ordinary C provider supplies authority.
- Providers have complete writable initialized inputs without relocations or
  other allocated payload. Imports are aligned bounded R32 relocations with
  zero addends to unique actual global named bases. Zero ELF sizes admit only
  those bases. Group membership and order are explicit recipe dependencies.
- Fresh compiler input/output, actual ordinary group/link commands and products,
  source/recipe/tool snapshots and loaded-byte observations remain held. The
  unique final map independently authenticates current canonical provider rows,
  contiguous complete allocations and the original runtime origin. It is not
  a pre-link object prerequisite.
- Derive source identities first from real raw imports and group definitions.
  Compare the entire source-owned runtime record set afterwards: exact count,
  sites, type, order, operation, LOCAL base and full target. No missing record
  may be backfilled through compatibility borrowing. Replacing the first pointer
  with NULL must fail even when its configured word remains zero.
- Ordinary replay must reproduce the entire configured aggregate, including all
  nonrelocation scalar bytes. Metadata-only container conversion preserves the linked payload. The
  authentic raw source object and original relocation records remain separate;
  ordinary ld legitimately relocates initialized DATA.
- Failed/stale revalidation exposes no earlier provider authority or cached
  inventory. Stable raw/provider paths and private prerequisite profiles must
  remain meaningful Make dependencies; repeated unchanged builds are no-ops.

## Consequences

This is a bounded same-module grouped LOCAL named-base case. It grants no
arbitrary interiors, implicit compiler-pool grouping, cross-module non-ORT
imports, source-only build, executable credit, BSS ownership, native-port claim
or general C alias-safety closure. Existing legacy consumer views remain explicit
debt. Unselected tail and retained layout authority remain borrowed.

Validate actual ordinary linking and whole-input reproduction, first-NULL
relocation loss, wrong/missing/duplicate providers, role/order/addend errors,
held mutation and warm-cache/dependency behavior. Adoption additionally requires
all unaffected identities, complete runtime tables, exact full ROM and normal
gates. Only an independently proved residual delta may ratchet down.
