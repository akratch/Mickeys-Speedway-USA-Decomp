# Campaign efficiency: evidence before more attempts

This guidance is tracked in the public canonical repository. ADRs remain
authoritative, especially the matching standard, lane isolation, ADR 0017's
causal exploration packets and ADR 0018's progress-based stopping rule.

## Scheduling

Refresh the ranking after measurement inputs change and require complete
freshness before expected-yield selection. Then run the assignment gate for
each exact symbol/path identity. A ranking row is scheduling evidence, not
configured full-TU, relocation, or linked-ROM proof. A filtered near-match
view is not a census of the whole queue.

Use the compact function probe before an expensive investigation. Keep its
extent, frame, relocation, and source-lever findings together with the actual
candidate object. A few differing words do not imply a cheap remaining fix:
check the plateau history and the named mechanism before allocating attempts.
Do not turn a scheduler/allocation category into an assumption of reachability.

ADR 0016 governs ordinary escalation and standing sweeps. An explicitly
authorized ADR 0017 causal packet may investigate structural deficits beyond
that narrow threshold, with authenticated ownership and baseline context. Stop
after three consecutive attempts yielding no improvement, proved identity or
eliminated hypothesis under ADR 0018; close before editing when the assigned
mechanism is already ruled out. Neither route grants an unrestricted reopen.
Tool faults are repaired as operational work; do not charge them to a source
permutation hypothesis or invent a lever merely to pass an assignment filter.

Keep parallel lanes disjoint by source ownership, not just by symbol spelling.
Several symbols in the same TU benefit from one context investigation and
shared baseline compile; they do not justify simultaneous conflicting edits.
When work is ready, run independent fresh-target work, bounded sweeps, and
reusable compiler investigations in parallel. Never fill capacity by repeating
an exhausted mechanism without new evidence.

## Tool acceptance criteria

| Surface | Required evidence before relying on it |
| --- | --- |
| Ranking freshness | Current live membership; actual configured command, source/TU, headers, target and tools agree with what was measured; unchanged refresh avoids compilation |
| Integration transaction | Exact reviewed generated delta, including regenerated deletions; unrelated edits preserved; gate/hook failures leave the merge uncommitted; real ROM integration passes |
| Compact probe | Configured preflight and diagnosis compose without hiding missing identities or size drift; failed/partial phases remain non-success; no promotion or source mutation |
| Structural ranking | Shift-sensitive synthetic regressions; live and resumed ranking agree; nondominated alternatives retained; exact verification predicates unchanged |
| Sweep receipts | Actual prepared source/compiler/settings identity; failures retry; bounded execution; atomic durable state; retained best artifacts survive lane cleanup |
| Raw assembly census | Parsed ownership boundaries; zero-filled declared padding verified from ROM; tiny executable tails remain work; resident uncertainty and scaffold-only changes earn no credit |

Unit tests do not stand in for exercising the configured toolchain. Include
negative cases that would otherwise look successful: an ignored/recreated
generated file, a changed per-TU define/include, line-sensitive source changes,
an unsupported relocation, a partial lattice, or a nonzero subprocess exit.
Keep every ROM-derived test artifact ignored and local; committed regressions
use synthetic evidence.

## Measuring the payoff

Lead campaign reports with newly ROM-exact executable bytes and function-sized
commits. Separately report ownership-only carving, improved non-exact
candidates, repaired tool faults, and publication state. Track elapsed time,
compile/cache reuse, search attempts and exact promotions in untracked runtime
receipts; never infer throughput from a commit count or a declining diff score.

Evaluate tooling against repeated work removed or exact closures enabled.
Extend the workbench when a concrete recurring blocker lacks a diagnostic or
source-search control, not merely because another metric can be displayed.
Keep scalar words for continuity, structural evidence for comparing different
candidate shapes, and linked-range/relocation/ROM gates as the final authority.

Publish reviewed exact changes through `campaign/unchain` and `tools/land.sh`
only after the required proof and integration gates. The canonical origin is
public; there is no private mirror or later publication boundary. Keep raw
ROM-derived captures and lane receipts ignored; concise permitted evidence
notes still follow the clean-room and commit rules.
