#### 2026-10-02, lane z-track: 2 to 0, promoted

The two words were the else arm's surfaces base. ugen evaluates a binary
node's heavier operand first and its left operand on a tie
(`eval_2ops`), so no single expression tree for `base + (index << 4)` can
load the base between the index load and the scale: the scale's subtree is
always contiguous. The 900 single-expression spellings recorded below are
that fact measured. The order needs two statements whose second uopt folds
into the first.

The form that does it is Diddy Kong Racing's (`src/tracks.c`,
`var = collisionFacets[j].basePlaneIndex << 2; collisionPlanes[var]`): the
index is shifted by two into a local, and the planes are subscripted as an
`f32` array by that local. uopt combines the two shifts into one shift by
four and forwards the index as an unnamed value rather than colouring the
local, and the add keeps the base as its first operand. Direct-compile
measurements, masked words at delta 0:

- `local = index; planes[local * 4]` (f32 planes): base, then the index
  load in a scratch register, then the scale. 20 with a fresh local.
- `local = index << 2; planes[local]` (f32 planes) with a fresh `s32`
  local: the else arm is exact; 11 words left, all three spill homes four
  bytes low because the new local takes a frame cell.
- The same pair assigning the block's existing scratch local (the
  visibility word, dead after its two tests): 0.
- The same pair with a fresh local and the sort's flag carrier merged into
  `segmentNumber`, `segmentCount`, `x` or `z`: 0 as well; into
  `triangleIndex` 2, into `batchFlags` or `compareMask` 39 at +8.
- `local = index; &surfaces[local]` (TrackPlane planes): the index is
  coloured v0, 48. The f32 subscript is the part that matters.

`gmake verify` printed the expected SHA1 with the guard removed. The same
pattern is the open +0x1A8 group of `func_8001398C` and appears twice in
`func_80011980`. A scan of the linked ROM for a scratch-register index
load, a scale, and an add taking a scratch-register base first found it in
these three functions and nowhere else in game code.

#### 2026-10-02, lane x-track, second pass: the uopt trees (still 2)

`-Wo,-zdbug:2` listings (instrumented toolchain; the stock `uopt` aborts in
`wrapper_ecvt`) on mini TUs show why no spelling of the else arm's lookup
moves the surfaces base. Local optimisation already holds the address as
`uadd(ushl(uilod(...), 4), uilod(base))`: the multiply is lowered to a
shift and uopt puts the deeper operand first, so the code generator emits
the index load, the shift, then the base. Only a declared index variable
reverses the operands, `uadd(uilod(base), ushl(k, 4))`, and that variable
is coloured (v0 in the real function, s0 when the carrier is `surface`),
so the target's index load in a scratch register is lost and the ring
shifts by one draw (37 to 48 words). Measured flat at 2: cast round trips
on the base and the index (`(TrackPlane *) (s32) base`, `(s32)`/`(u32)`
index), `idx * sizeof(TrackPlane)` on a byte pointer, eleven dead-store
carriers into locals dead in that region (the store is removed before it
can make a CSE temporary), `u16` and `s32` block-scope carriers (48, they
also add a frame slot). A CSE of the index used twice in one block is
coloured too (mini TU). The target therefore draws the base between the
index load and its scale through a tree this lane has not reproduced.

#### 2026-10-02, lane x-track, third pass: the order is not a spelling (still 2)

The target's add takes the base as its first operand and the scaled index
second, and its ring names put the base draw between the index load and
the scale; the same holds at func_8001398C +0x1A8. Mini TUs with the
tree's IDO, read from `cc -S`:

- 900 single-expression spellings (10 index forms, 6 base forms, 15
  combining forms, in an else arm that feeds a pointer local) all emit
  index load, scale, base load. Six deeper base trees (cast chains,
  `*&*&`, a wrapper struct, a ternary) do the same.
- A true array base keeps a `uixa` node in uopt's listing and still scales
  before it forms the base; a pointer-to-array base scales first too.
- Base-then-scale appears only when the index is a separate statement's
  value: a declared scalar, one-field struct or union is coloured (v0/v1);
  an array element or address-taken cell is stored and reloaded; a scalar
  left uncoloured under register pressure is stored and reloaded too. None
  leaves the index in a scratch register.

So the two words need the index held across a statement boundary in a
scratch register, which no construct measured here produces. Next: read
ugen's handling of an add whose second operand is a shift (the
instrumented ugen's call stack on a carrier case names the handler) to
learn what makes it evaluate the first operand late.
