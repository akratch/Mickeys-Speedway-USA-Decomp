Four things were wrong with the inherited shape, and the records name three
of them.

The float parameters are not copied. The candidate carried the first float
argument in a declared local and negated the copy; the target negates the
parameter in place. On its own that edit looks like a disaster (88 words, no
frame, the zero constant no longer hoisted), which is why the earlier pass
recorded the carrier as load-bearing. The reason is the next point.

The result variable is initialised to zero together with the two
accumulators. The store is dead and emits nothing, but it gives the result
its web number ahead of both float parameters, so it is coloured first and
takes the third float colour. A parameter web is offered only the first four
caller-saved float colours or a callee-saved one, so the first float argument
then takes the fourth, the second finds none left and takes the callee-saved
register -- which is where the frame comes from -- and the last two
caller-saved colours stay free for the scratch value and the hoisted zero.
The initialiser must come after the two accumulators; before them it costs 24
words.

The early exit is one conditional expression, not two return statements. Its
value is a compiler temporary copied to the return register in each arm,
which is the target's shape; two returns write the return register directly
and are two instructions shorter.

The loop bound is written as the conversion itself and the named distance is
assigned after the loop. Assigning it before the loop and reading the name in
the loop condition keeps a second copy of the conversion in its own register
and costs one instruction. Assigning it inside the loop body, or writing the
loop as an endless loop with a break, are also exact.

The `goto` into the sibling arm was an artefact too: each arm sets the result
from the acceleration separately.
