Traced uopt builds (`build/54b3c-compose/fable/jtrace.py`, `ktrace.py`
against a rebuilt `uopt.c` with print points) settled the three open
mechanisms; workbench laws L173 and L174 carry them:

- **Frame.** frame = align8(0x28 + ugen area + uopt locals), and the uopt
  locals size covers the 35 homes plus slots only up to the highest slot
  uopt actually references. The target references none: 0x28-0x44 are
  ugen's eight words, 0x48 is an untouched request, 0x4C-0xD4 are the
  35 homes (0x50 unused). So the two position-pointer webs may request
  slots freely; the candidate's +16 is exactly the four referenced
  temporaries 4a, b^2, 2a, -b. In the target those values sit in the
  homes of z1, z2, x1, twoZ1, so they are kept symbol webs saved by ugen
  (z1/z2 coloured f2/f14, x1/twoZ1 memory) while emitting the same
  instructions the inline form emits.
- **The pointer recompute** in the quadA block is a Morel-Renvoise
  insertion (`insert` on the join, `delete` on the coordinate block);
  only a missing partial availability or a broken anticipation removes
  it, and both refold the distance loads. It costs no frame, so it is not
  a defect of the candidate.
- **What keeps the four quadratic assignments** is still open: the
  substitution rules keep `z1 = 4.0f * quadA` only when the second
  discriminants read z1 directly (`mpy_operand_op`), and then the merged
  coordinate+quadratic web prices above N/4 and takes f22; `z2`, `x1`,
  `twoZ1` have no natural keep (`sub`, compare, `div` uses). Memory-class
  quadA/quadB keeps all four but drops the FP pressure that produces the
  coordinate cadence (-32 bytes). Extra empty blocks (N/4 lever) worsen
  it. The `y2 = z1` carrier lowers z1's save to the split threshold but
  loses the keep.
- **The z2 hoist** (L168) is the other open item; it costs the natural
  spelling masked 334 against the diagnostic 83.

#### The hoist is killed naturally (permuter, same day)

A 45-minute `tools/permute.sh` run on the inline-quadratic base found the
spelling every hand sweep missed: take the address of the field into the
existing pointer local in the step block and read it back,

```c
addr = &secondPoint->z;
...
z2 = *addr;
```

That read is a different code-motion item from the distance block's
`secondPoint->z` (workbench L175), so nothing is hoisted, no temporary is
made, and ugen folds the address back into the same `8(reg)` load.
`build/54b3c-compose/fable/pz2.c`: masked 70, size delta 0, 368 of 370
shape rows, and the instruction stream is now **identical to the target**;
the 70 are stack offsets, because the frame is 0xE8 against 0xD8 (the four
referenced uopt temporaries for 4a, b^2, 2a, -b where the target owns
homes). `wa.c` adds `x1 = 2.0f * quadA; twoZ1 = -quadB;` inside the root
block (both address-taken): frame 0xE0, 366 rows, with one as1 scheduling
swap (a restore and the `mtc1 zero` constant) in the post-call block as the
only instruction difference. Open: that swap, and 4a/b^2 as kept symbols
z1/z2 without changing the colouring elsewhere.

#### The last swap is a colouring of twoZ1's root-block piece (agent O trace)

With `x1 = 2.0f * quadA; twoZ1 = -quadB;` restored in the root block
(`wa.c`, frame 0xE0, 366 rows), the as1 trace shows the remaining
